# Miku-ZSTD Velocity 6.0.0

作者：JunXieX　|　MikuMC系列插件交流群：1105054380　|　非开源项目，请勿二次分发

本目录是代理端插件。完整部署与配置以[根目录说明](../README.md)为准，以下列出代理服主最常用的操作。

## 功能特性

- 压缩代理向配套 Fabric 客户端发送的下行流量，上行继续按原版处理。
- 提供代理状态、连接排行与实例级 BossBar 监控。
- 6.0.0 默认关闭新配置的调试日志，并让无代理权限、已连接后端的玩家将 `bar` 交给后端自行鉴权。

## 环境要求

| 组件 | 当前基线 |
|---|---|
| Java | 25 |
| 代理 | Velocity 4.x，当前真实服务器登录回归使用 4.3.1 |
| 客户端 | Minecraft 26.2，Fabric Loader 0.19.5、Fabric API 0.160.0+26.2 构建基线及配套模组 |

其他版本是否适用应单独核对；本说明不把旧性能样本当作 6.0.0 实测结果。

## 安装

1. 将 `Miku-ZSTD-6.0.0-Velocity.jar` 放进代理的 `plugins/`，清理同实例旧副本。
2. 玩家将 Fabric 产物放进对应游戏实例的 `mods/`，并安装所需 Fabric 依赖。
3. 重启代理。首次启动生成 `plugins/Miku-ZSTD/config.yml`；客户端首次启动生成 `<游戏目录>/Miku-ZSTD/config.yml`。
4. 登录后用 `/mikuzstd status` 查看代理状态，F8 查看客户端下行统计。

后端 Paper 插件是独立选装项，代理压缩不以它为前置；后端面板也不会自动汇总代理出口。所部署的端建议统一 6.0.0，是否回落取决于协议 / 能力协商，而非只比较应用版本号。

配置目录由实际初始化入口解析为 `plugins/Miku-ZSTD/`；旧注入目录迁移失败时沿用原目录并记录日志，遇到配置修改无效先核对该日志。

## 配置说明

新文件的主要默认值：

```yaml
compression:
  level: 3
  window_log: 20
  threads: 0
  batch_window_ms: 50
  batch_max_packets: 64
  skip_compress_below_bytes: 48
logging:
  debug: false
```

`bossbar.format` 支持 `%players%`、`%raw%`、`%wire%`、`%ratio%` 与 `&` 颜色代码。全部字段说明与完整模板见根目录配置章节。

已有配置不会被覆盖，显式 `debug: true` 升级后仍为 `true`；只有新文件、空配置或缺省键采用关闭状态。

修改后由有代理权限的来源执行 `/mikuzstd reload`。调试开关、BossBar 文本、小包阈值即时读取；等级、窗口与批处理参数需新连接；线程数需重启代理。调试开关也控制每 60 秒一次的原始帧分桶剖析。

## 命令

| 命令 | 作用 |
|---|---|
| `/mikuzstd status` | 代理配置、在线人数与线程池状态 |
| `/mikuzstd top` | 代理下行连接排行 |
| `/mikuzstd bar` | 按代理权限与当前后端连接选择本地执行或转发 |
| `/mikuzstd reload` | 有代理权限时重载代理配置 |

`bar` 的三条规则：代理权限足则本地执行；无代理权限但玩家已连接后端则转发同一命令，由后端鉴权；无代理权限的控制台或无后端玩家收到明确提示。`status` / `top` 仍留在代理，`reload` 保留代理权限门槛。

## 权限节点

| 节点 / 身份 | 作用 |
|---|---|
| 代理 `mikuzstd.command` 或 `zstd.command` | 本地代理 `bar`、`reload`，由代理权限系统授予 |
| 后端 OP / 后端 `mikuzstd.command` | 只在命令已交给后端时参与后端鉴权 |
| 无额外权限 | 查询代理 `status` / `top`、切换客户端 F8 HUD |

后端 OP 不自动继承代理权限。有代理节点时 `bar` 优先代理，不会同时打开后端监控；两端都是各自实例的全局单观察者监控。

## 常见问题

- **子服 OP 想看后端监控：** 后端安装 Paper 产物并按后端规则授权；该玩家无代理节点时，`bar` 才交给当前后端。
- **想看代理出口：** 在代理权限系统授予节点后执行 `bar`，或直接用 `status` / `top` 查看文本。
- **有调试日志：** 检查是否保留了旧配置中的显式 `true`；改为 `false` 后重载。
- **数值与后端不同：** 观察的是不同实例实际处理的流量，先确认执行命令的层级。
- **压缩收益不明显：** 用实际流量观察，避免把历史示例当成当前服的保证；常见安装与阈值检查见根目录说明。
